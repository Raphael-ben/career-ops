# Mode: pro/write-cv — CV Writer

## Purpose
Generate a filled LaTeX CV tailored to a specific job description. Reads the profile bank and the candidate's CV template, produces a filled `{file_slug}_CV.tex` in the output folder (`{file_slug}` = `profile_bank.candidate.file_slug`). Every slot in the template is filled — no `%%FILL:` markers remain.

## Resolution — machine paths and profile bank

Resolve `{DATA_DIR}` and `{PYTHON}` from `modes/_profile.md` (lines `DATA_DIR: ...` / `PYTHON: ...`). If absent, `{DATA_DIR}` defaults to the repo's `config/` and `{PYTHON}` to `python3`. The **profile bank** is `{DATA_DIR}/config/profile_bank.json` (fallback: repo `config/profile_bank.json`). Read it once; every candidate-specific name, employer, grade, count, heading, and banned-term list below comes from it — this mode holds no personal literals.

## Inputs required before starting
- Job description text (provided by pipeline or pasted by user)
- Classification output: `role_type`, `industry`, `seniority`, `language`, `swiss` (true/false), and any conditional-inclusion flags the classifier emits (e.g. an eligibility flag per `profile_bank.rules.conditional_mentions` entity)
- Profile bank path (see Resolution)
- CV template + fill-spec: the candidate's `.tex` template and `cv-fill-spec.md` in `{DATA_DIR}/templates/`
- Output folder path (created by pipeline)

## Process

### Step 1 — Load inputs

Read `{output_folder}/profile-filtered.json` (pre-filtered profile for this job, generated by pipeline Step 3.5; if missing, read the full profile bank). Read `{DATA_DIR}/templates/cv-fill-spec.md` for LaTeX syntax reference.

**Resolve the template and photo via `config/profile.yml`** — do not hardcode a filename. Resolve the CV template via profile.yml `cv.template_cv` (the path may contain `{DATA_DIR}`; substitute it). Resolve the photo via profile.yml `cv.photo` (same `{DATA_DIR}` substitution) — this is the `\CVPhoto` value in Step 6. (`cv.template_cl` is the cover-letter template, used by write-cl, not here.) Read the resolved `.tex` CV template to copy its preamble verbatim when writing output. All fill conventions are already in this mode file.

### Step 2 — Extract JD keywords (ATS injection)

Extract 15-20 keywords from the JD: noun phrases and verb phrases the JD uses to describe required skills and experience. These will be woven naturally into experience bullets. Do NOT invent experience — only reformulate existing profile-bank content using JD vocabulary.

### Step 3 — Select and order experience blocks

Bullet allocation is **data-driven** — read `profile_bank.rules.bullet_counts` (one entry per experience block with a fixed rule) and `profile_bank.rules.classification_defs`. For each block, work top of the array down.

**Mandatory blocks first.** Any block with `always_include: true` is included in every CV. Assign its `default` bullets (or `default_max` when a range is allowed and the page has room).

**Bullet count — MANDATORY explicit classification, one statement per block that has a `reduce_when`:**

For each such block, before assigning its bullet count you MUST state your reasoning inline and **quote the rule data verbatim**:

1. Quote `bullet_counts[block].reduce_when` verbatim (and any `classification_note`).
2. Quote the relevant `classification_defs` entry that `reduce_when` references, verbatim.
3. State whether the current role's classification satisfies `reduce_when`.
4. State the resulting count: `default` if it does not apply, `reduce_to` if it does.

Emit the statement in this exact shape, one per block:
`[{block}: {N} bullets — reduce_when="{quoted}"; classification is {role classifications}; {applies / does not apply}]`

Do not paraphrase the condition into your own words instead of quoting it — the quote is the guard against drift.

**Space-fill rule — MANDATORY, run after assigning mandatory bullets.** Read `profile_bank.rules.space_fill`:

Step A — compute base count using `space_fill.base_formula` verbatim (it names exactly which block bullet-counts and which education blocks sum into `base_count`).

Step B — decide each `space_fill.optional_blocks` entry, in array order. For each entry:
- Quote its `condition` verbatim, then state whether it fires for this role.
- If `absolute: true`, the `condition` is the ONLY gate — space-fill must NEVER override it (neither to add nor to drop the block). State: `[{block}: condition absolute — included/excluded by condition only]`.
- If `absolute: false`, include the block when the `condition` is true (the condition may be an OR of a market/role predicate and a `base_count < fill_threshold` predicate — quote `space_fill.fill_threshold` and `fill_threshold_note` when the numeric branch decides it).

State each decision explicitly, e.g.: `[{block}: included — base_count={n} < fill_threshold={t}]` or `[{block}: excluded — not market-facing and base_count >= fill_threshold]`.

**Education selection.** Read `profile_bank.education` (entries) and `profile_bank.rules.education_display`:
- The flagship degree bullet: if `education_display.cgpa_show_in_cv` is true, it must include `education_display.cgpa_value`; if `education_display.cgpa_must_open_mba_bullet` is true, the bullet must OPEN with that figure. Use `education_display.mba_cv_bullet_canonical` as the canonical full text; never omit any of `education_display.mba_required_tokens`.
- Any conditional prep/foundation education block uses `education_display.prepa_cv_bullet_canonical` and is included only when the space-fill rule above triggers it (see its `optional_blocks` entry) or the role matches its `conditional_mentions` gate.
- Other always-on education blocks: 1 bullet each, expanded from their `notes`.
- **Education bullet minimum length:** every education bullet must be at least `education_display.min_education_bullet_chars` rendered characters (excluding LaTeX commands). Thin single-clause bullets must be expanded using all available `notes` content from the profile bank. Never show individual course grades if `education_display.no_individual_course_grades` is true — only the overall figure.

**Achievement selection:** within each role, only surface achievements where `achievements[].surface_in` includes at least one of the role's classifications. Prefer `confidence: "high"`; use `"medium"` sparingly.

**Eligibility precedence (rule count vs. eligible achievements).** The rendered bullet count for a block = min(rule-derived count, achievements eligible via surface_in ∩ classification, where surface_in containing "general" is a wildcard that matches every classification). A block never renders more bullets than it has eligible achievements, even when its rule asks for more. The NOMINAL rule-derived counts (before this min) are still what `space_fill.base_formula` uses — base_count sums the nominal counts, not the possibly-smaller rendered counts.

**Titles in the JD language.** The experience-block title is `experience[].title_localized[<lang>]` where `<lang>` is the JD/classification language (en/de/fr); fall back to `experience[].role` only when that language key is absent. Never render an English title in a non-English CV (this is what prevented an English 'Engineer Intern' from appearing in a German CV). ALL rendered text — titles, bullets, sidebar, tagline, section headings — must be in the JD language. Apply every `profile_bank.rules.framing` rule whose `enforce_on` includes `cv` (read each `rule` + `explanation` and apply it — e.g. a role that must never be framed as an internship uses its real stored title).

### Step 4 — Apply standing rules

Read `profile_bank.rules`. Apply all constraints:

- **never_mention**: never use any term in `profile_bank.rules.never_mention` — anywhere (bullets, sidebar, tagline). Even if a template instruction example shows such a term, do not put it in the actual content. Where a banned term names a real skill, describe the work generically instead (the `framing` rule for it says how).
- **framing**: for each entry in `profile_bank.rules.framing` with `cv` in `enforce_on`, read its `rule` + `explanation` and enforce it (verbatim titles, no-internship framing, single-page discipline, ATS mirroring, etc.).
- **tense**: read `profile_bank.rules.tense.departure_date`. A role whose `end_status` is `current_indefinite` or `contract_ending` and whose end is on/after today uses present tense; every completed role (and any role ended before today) uses past tense.
- **conditional_mentions**: for each entry in `profile_bank.rules.conditional_mentions`, the `entity` may surface ONLY when the role's classification is in `surface_only_when`. This is absolute — Step 3's space-fill never overrides a conditional-mention gate.

### Step 5 — Compose sidebar content

**All section headings are data-driven and in the JD language.** Every heading the template renders — `professional_experience`, `education` (both via `\mainSection` in Step 6), `foreign_languages`, `personal_skills`, `computer_skills`, `extracurricular`, `contact_details` — comes from `profile_bank.rules.section_headings.<section>[<lang>]`, where `<lang>` is the JD/classification language. Use the stored string exactly; never a literal translation, and never any string in `section_headings.<section>_banned[<lang>]`. The template hardcodes some labels (its preamble ships `\sidebarSection{CONTACT DETAILS}` in the `contactBlock` environment and English `\mainSection{...}` titles); when filling, **override every hardcoded heading with the `section_headings` value for the JD language** — e.g. replace `CONTACT DETAILS` with `section_headings.contact_details[<lang>]` (KONTAKT for de, CONTACT for fr).

**FOREIGN LANGUAGES** (from `profile_bank.candidate.languages`): heading = `section_headings.foreign_languages[<lang>]`. Map each `level` to its display label via `profile_bank.rules.language_level_labels[<lang>]` (the JD-language map — e.g. `de.C1` = "Fliessend", `fr.native` = "Langue maternelle"). Use `\sline` (most items are too long for `\pair`).

**PERSONAL SKILLS** (6-10 items from `skills_master.soft` + qualitative `skills_master.domain` items): short 1-3 word items, mix both groups, tailor to classification. Use `\pair` for short items (≤18 chars), `\sline` for longer.

**COMPUTER SKILLS** (5-9 items from `skills_master.tools` + technical end of `skills_master.technical`): tool and language names only. NEVER include a tool not in `profile_bank.skills_master.tools`. Never emit any `never_mention` term.

**EXTRA-CURRICULAR block** — always include; never emit it empty. **Section heading by CV language:** read `profile_bank.rules.section_headings.extracurricular[<lang>]` and use it exactly; never a literal translation of "extra-curricular activities", and never any string listed in `section_headings.extracurricular_banned[<lang>]`. **Content** is data-driven from `profile_bank.rules.extras` (order in the array is priority order for space-filling): include each `item` whose `condition` holds — `"always"` items always; classification-predicate items only when the role classification matches (some `extras` conditions reference a `conditional_mentions` entity's `surface_only_when` — resolve it against the classification); `space_fill:` items only to bring the block up to size when space allows. Minimum block: the always-on item(s) + at least one more.

Sidebar `\pair` / `\sline`: items ≤ ~18 chars → `\pair`; longer → `\sline`. One leftover short item at end of a group → `\sline`.

### Step 6 — Fill the template

Escape identity values per cv-fill-spec before writing any `%%FILL` marker (name, address, phone, email, tagline, photo path).

Filling conventions from the template's fill-spec:

**User variables block** — fill at top of preamble from `profile_bank.candidate`:
```latex
\newcommand{\CVName}{<candidate.name>}
\newcommand{\CVTagline}{Line 1 positioning,\\[2pt]Line 2 if needed}
\newcommand{\CVPhoto}{<photo resolved from profile.yml cv.photo in Step 1>}
\newcommand{\CVAddress}{<candidate.contact.address, split across lines>}
\newcommand{\CVPhone}{<candidate.contact.phone, LaTeX-spaced>}
\newcommand{\CVEmail}{<candidate.contact.email>}
```

**Tagline**: 1-2 lines positioning the candidate for this specific role, in the JD's language register. If no role-tailored line is warranted, fall back to `profile_bank.candidate.tagline.default`. **Max `profile_bank.candidate.tagline.max_chars_per_line` characters per line** — count characters before writing; shorten or abbreviate if a line would exceed the cap.

**Experience blocks** — one per selected role, most recent first:
```latex
\begin{experience}{date range}{job title}{company}{location}{company URL}
  \item Bullet text
\end{experience}
```
Date format: `Month.~'YY -- Month.~'YY` for completed; `Month.~'YY -- present` for a current role. Abbreviated months. Special chars: `\&`, `\%`, `\_`. No curly quotes (straight ASCII). No `\vspace` in the body.

**Education blocks** — after the education section header:
```latex
\begin{education}{date range}{degree}{institution}{location}{URL}
  \item Note or distinction
\end{education}
```

### Step 7 — ATS keyword injection

Integrate the 15-20 JD keywords naturally into filled bullets. Reformulate existing achievements using JD vocabulary. Never invent experience not in the profile bank.

### Step 8 — Swiss German orthography

If `swiss: true`: use `ss` instead of `ß` throughout all bullet text, sidebar items, and tagline. The LaTeX compile script applies a second pass, but the mode output must already be clean. If `swiss: false` and the company is German (DE): use standard `ß`.

### Step 9 — Page fullness self-check (planning aid before compiling)

**Compute — do not estimate.** Fill this table explicitly before writing the file:

| Element | Count | Lines each | Subtotal |
|---------|-------|------------|----------|
| Section headers (EXPERIENCE, EDUCATION) | 2 | 2 | 4 |
| Section gap | 1 | 1 | 1 |
| Experience blocks | _N_ | 4 | _4N_ |
| Education blocks | _N_ | 4 | _4N_ |
| Bullets < 90 rendered chars | _N_ | 1 | _N_ |
| Bullets 90–175 rendered chars | _N_ | 2 | _2N_ |
| Bullets > 175 rendered chars | _N_ | 3 | _3N_ |
| **TOTAL** | | | **??** |

Rendered chars = strip `\item`, all LaTeX commands, count remaining visible characters. Bullets at 160–175 chars with dense caps/numbers can silently wrap to 3 lines — count them as 3.

**Target: `profile_bank.verify.tolerances.cv_target_lines_min`–`cv_target_lines_max` estimated lines** for a comfortably full single page.

If computed total is under target, expand in this order (stop when in range): expand short bullets (< 90 chars → ≥ 100, using real achievement detail); expand education bullets from `notes`; add a not-yet-surfaced `surface_in`-compatible bullet to a block still below its `bullet_counts.default`; add the conditional prep education block if its space-fill trigger now fires. Never pad with content not in the profile bank; never exceed 3 lines per bullet.

If computed total is over target, trim in this order: shorten the longest bullet from 2 lines to 1; remove the lowest-priority optional bullet; remove the conditional prep block; drop the flagship-experience block to its `reduce_to`/`default` floor.

**This hand table is a ROUGH planning aid only. It is NOT the gate** — character counts do not predict rendered fill. The hand-table typically OVERESTIMATES by 5-15% at high bullet density; never trim before compiling — only the Step-10 measured gate decides. The real gate is Step 10.

### Step 10 — Emit, compile, and pass the measured fill gate

**The real gate is measured fill on the compiled PDF — and the loop is by SELECTION, not rewriting:**

1. Emit the CV from the **full humanized bullet set** — every eligible bullet at its natural, rule-compliant length. Do NOT pre-trim, do NOT em-dash-pad or invent connective prose to hit a number (that is how slop and banned em dashes get in).
2. Write `{output_folder}/{file_slug}_CV.tex` (`{file_slug}` from `profile_bank.candidate.file_slug`).
3. Compile: `cd {output_folder} && pdflatex -interaction=nonstopmode -halt-on-error {file_slug}_CV.tex`.
4. Measure: `{PYTHON} cv_fitcheck.py {output_folder}/{file_slug}_CV.pdf` (real main-column fill via PyMuPDF; PASS = ≥ `profile_bank.verify.tolerances.cv_min_fill_pct`% fill, single page, AND non-negative bottom blank / margin). Optionally add `--ats --expect "<candidate.name>"` to also gate that the PDF's text is machine-extractable, the identity is present, and column order is stable.
5. **Loop until PASS, adjusting only by selecting whole humanized units:**
   - **Overflow (> `cv_max_pages` page):** drop the lowest-priority WHOLE bullet (conditional prep block → last optional experience bullet → weakest flagship bullet), then recompile.
   - **Underfilled (< `cv_min_fill_pct`%):** restore a dropped bullet, or swap a bullet for its fuller profile-bank variant, then recompile.
   - Never close the gap by rewriting prose, padding, or inserting em dashes.

`verify.md` Step 0 runs this same measured gate and blocks the pipeline on its exit code.

Report — all fields mandatory:
- EXP blocks included (list of experience ids)
- Keyword list injected
- **Bullet-count classifications:** copy each per-block `[{block}: ... reduce_when="..."; ...]` statement verbatim
- **Optional-block decisions:** copy each `[{block}: included/excluded — ...]` statement verbatim (conditional-mention blocks + space-fill blocks)
- **Step 9 line-count table:** copy the completed table verbatim
- **Fill gate result:** paste the `cv_fitcheck.py` output line — `PASS (≥{cv_min_fill_pct}% fill, single page)` or `FAIL — {what was selected/adjusted}`
- Any standing rules triggered

## Hard rules — violations cause verifier to fail

1. **Source-bound claims.** Every bullet maps to a specific achievement in the profile bank. No claim untraceable to an experience/achievement id.
2. **No invented metrics.** Numbers only if in the profile bank.
3. **No inferred sector specifics.** Do not claim engagements in a JD sector unless the profile bank states it.
4. **No banned terms.** Never emit any `profile_bank.rules.never_mention` term.
5. **Tense compliance** per `profile_bank.rules.tense` (see Step 4).
6. **Single page.** If content overflows, trim bullets — do not adjust geometry.
7. **Never devalue the profile.** No "without hierarchical power", no "the project wasn't technically complex", no "I did not have...".
